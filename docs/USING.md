# 사용법

[README](../README.md) / `docs` — [ARCHITECTURE](ARCHITECTURE.md) · [USING](USING.md) · [COMMANDS](COMMANDS.md) · [VENDOR](VENDOR.md)

Refdex를 띄우고, 읽을 폴더를 지정하고, 네 개의 패널을 쓰는 방법. 빌드와 배포 명령은 [COMMANDS](COMMANDS.md)에, 내부 구조와 그렇게 정한 이유는 [ARCHITECTURE](ARCHITECTURE.md)에 있다.

## 읽을 폴더를 정하는 두 가지 방법

**앱은 읽을 폴더를 어디에도 저장하지 않는다.** 그래서 실행할 때 알려 주거나, 창에서 직접 고르거나 둘 중 하나다.

**바로가기에 지정한다.** 바로가기 속성의 대상 끝에 폴더 경로를 붙이면, 누르는 즉시 그 폴더로 열린다. 아무것도 묻지 않는다.

```text
refdex.exe "D:\Projects"
```

폴더마다 바로가기를 따로 두면 `Refdex — 개인`, `Refdex — 회사`처럼 쓸 수 있다.

**창에서 고른다.** 인자 없이 실행하면 시작 화면에 `Open folder` 버튼이 뜬다. 연 뒤에도 왼쪽 위 `PROJECT` 옆 버튼으로 언제든 다른 폴더로 옮길 수 있다. 그 버튼에는 지금 읽고 있는 폴더 이름이 폴더 아이콘과 함께 적혀 있어서, 어디를 보고 있는지도 거기서 확인한다. 이렇게 고른 폴더는 **그 창에서만 유지되고 창을 닫으면 잊는다.**

설치 파일이 만드는 바로가기에는 인자가 없다. 그래서 설치 후 처음 실행하면 시작 화면이 뜬다 — 위의 방법으로 폴더를 한 번 지정해 두면 그다음부터 바로 열린다. **폴더 지정은 사용자가 한다. 앱은 기억하지 않는다**([D49](ARCHITECTURE.md)).

어느 쪽이든 지정하는 것은 **프로젝트들이 들어 있는 상위 폴더**다. 프로젝트 하나가 아니다.

## 폴더 구조

Refdex는 폴더에 아무것도 쓰지 않으므로, 무엇을 보여 줄지는 **이미 있는 파일의 이름**으로 판단한다.

| 두는 것 | 위치 | 결과 |
| :--- | :--- | :--- |
| `.md` 하나 | 폴더 아래 어디든 | **이것만으로 프로젝트가 된다.** 왼쪽 위 목록에 나타난다 |
| 셸 코드 블록 | 그 프로젝트의 어느 문서든 | 왼쪽 아래 명령 패널의 한 줄이 된다 |
| `README.md` | 프로젝트 폴더 최상단 | 프로젝트를 고르면 처음 열리는 문서 |
| `CLAUDE.md` | 프로젝트 폴더 최상단 | `README.md`가 없을 때 처음 열리는 문서 |
| `graphify-out/graph.html` | 프로젝트 폴더 최상단 | `Graph` 탭에 그대로 표시된다 |
| 그 밖의 `.md` | 어디든 | 다른 문서가 링크해야 도달한다 |

**아무것도 두지 않아도 된다.** 요구하는 파일 이름은 없다 — `.md`가 하나라도 있으면 그 폴더가 목록에 올라간다. 두 이름만 의미가 있고, 그것도 **무엇이 먼저 열리는가**만 정한다: 최상단의 `README.md`, 없으면 최상단의 `CLAUDE.md`, 둘 다 없으면 경로 순서상 **첫 문서**가 열린다. 두 이름은 대소문자를 구분하지 않고(2026-11-20) **프로젝트 폴더 최상단**에 있어야 한다 — `docs/README.md`는 그냥 문서 하나다.

**`.md`가 아닌 파일은 화면에 들어오지 않는다.** 이미지는 문서 안에서만 보이고, `graphify-out/graph.html`은 전용 탭에 뜬다. `.js`든 `.txt`든 `.pdf`든 목록에도 검색에도 나오지 않는다.

```text
지정한 폴더/
├── project-a/
│   ├── README.md          ← 고르면 이것이 열린다
│   ├── CLAUDE.md
│   └── graphify-out/graph.html
└── project-b/
    ├── README.md
    └── docs/
```

프로젝트를 추가하는 데 설정은 없다. 폴더를 만들고 `.md` 하나를 두면 3초 안에 목록에 나타난다. **반대로 목록에서 빼는 방법은 없다** — 숨기려면 어딘가에 기록해야 하는데, 그 기록할 자리를 두지 않기로 했다([D22](ARCHITECTURE.md)).

## 네 개의 패널

```text
┌──────────────┬────────────────────────┬──────────────┐
│ PROJECT      │ Search │ Hist │ Term │ Graph │        │
│ (좌상단)      │                        │  Document    │
├──────────────┤   선택한 탭이 전체를     │  (오른쪽)     │
│ COMMANDS     │        차지한다          │              │
│ (좌하단)      │      (가운데)           │              │
└──────────────┴────────────────────────┴──────────────┘
```

왼쪽은 **고르는 곳**, 가운데는 **작업하는 곳**, 오른쪽은 **읽는 곳**이다.

| 패널 | 내용 |
| :--- | :--- |
| PROJECT | 지정한 폴더 아래에서 찾은 프로젝트 목록. 파일은 나열하지 않는다 |
| COMMANDS | **그 프로젝트의 모든 문서에서 모은 셸 코드 블록.** 줄마다 그 블록이 속한 제목과 문서 이름이 함께 표시된다. 제목을 누르면 오른쪽 패널이 그 문서의 해당 위치로 이동한다 — 실행하기 전에 설명을 읽을 수 있다. **순서는 문서 경로 순이고, 한 문서 안에서는 위에서 아래다** — 자주 쓰는 명령을 문서 위쪽에 적으면 패널에서도 위에 선다 |
| Document | `.md`를 그린다. 프로젝트를 고르면 `README.md`, 없으면 `CLAUDE.md`가 열리고, 그다음부터는 문서 안의 링크로 이동한다. 맨 위에는 지금 보는 문서의 경로만 적힌다 |

**패널 사이 경계 3개는 드래그로 조절한다.** 각 경계는 양옆 패널하고만 너비를 주고받으므로, 문서 패널을 넓히려면 그 왼쪽 경계를 끈다. 조절한 너비는 이 브라우저에 저장되어 다음에 열 때 그대로 적용된다(2026-11-17). 끝까지 끌어도 패널이 사라지지는 않는다 — 문서 440px, 가운데 200px, 왼쪽 160px, 상하 120px에서 멈춘다(2026-11-22).

**밝은 테마와 어두운 테마는 OS를 따라간다.** 선택하는 설정은 없고, 창 제목 표시줄 색까지 함께 바뀐다(2026-11-22).

## 가운데 탭 넷

선택한 탭 하나가 패널 전체를 쓴다. 어느 탭이었는지는 저장하지 않아서 열 때마다 검색부터 시작한다.

### Search

**지금 디스크에 있는** 문서의 본문과 경로를 검색한다. 30건까지 보여 주고 탭 이름 옆에 건수가 뜬다. **본문과 경로를 함께 보므로 파일 이름으로도 찾을 수 있다.** 이름이 일치한 것이 먼저 나온다.

손을 키보드에서 떼지 않고 쓸 수 있다 — **↓↑로 고르고 Enter로 열며**, 아무것도 고르지 않은 상태의 Enter는 첫 번째 결과를 연다. Esc는 입력창을 비운다(2026-11-22).

문서는 처음 한 번만 전부 읽고 그다음부터는 읽어 둔 내용을 검색한다. 문서 1,008개(540만 자)로 측정했을 때 **첫 검색 4.2초, 이후 11~15ms**였다(2026-11-22).

### History

그 프로젝트의 **커밋 기록**이다. 입력창 하나로 세 가지를 오간다.

| 입력창 상태 | 보여 주는 것 |
| :--- | :--- |
| 문서 경로 (탭을 열면 자동으로 들어온다) | **그 문서의 커밋 기록** |
| 비어 있음 | **프로젝트 전체의 커밋 기록** |
| 다른 단어 | 그 단어가 든 커밋 메시지 + **그 이름으로 존재했던 문서**의 커밋 |

마지막 것이 **삭제된 문서에 도달하는 유일한 길**이다 — 지금 없는 문서는 오른쪽 패널에 띄울 수 없고, 띄울 수 없으면 그 기록도 물을 수 없다.

입력창 위의 회색 줄은 **브랜치 이름**이다. 지금 보고 있는 커밋 기록이 어느 브랜치의 것인지 알려 준다. 브랜치를 바꾸는 기능은 없다([D46](ARCHITECTURE.md)) — Refdex는 저장소를 수정하지 않는다.

줄을 누르면 **커밋 메시지 전문**이 펼쳐지고 그 아래에 바뀐 줄이 나온다. 삭제된 줄은 빨강, 추가된 줄은 초록으로 한 줄씩 따로 표시되고, 바뀐 부분은 진하게 강조된다. 바뀐 줄은 **그 변경이 속한 제목**으로 묶이고, 묶음을 누르면 오른쪽 문서가 그 제목으로 이동한다.

30개씩 보여 주고, 맨 아래 `older changes`를 누르면 다음 30개가 이어 붙는다. 이름이 바뀐 문서는 예전 이름의 기록까지 따라온다(`--follow`).

**저장소가 아니면** 그 사실을 적고, 그 아래에 `Start a record in this folder` 한 줄을 둔다. 실행 버튼을 누르면 터미널에서 `git init -b main; git add -A; git commit -m "Initial commit"`이 실행된다([D47](ARCHITECTURE.md)). 기계에 git이 없으면 이 줄은 나타나지 않는다.

### Terminal

**프로젝트마다 셸이 하나씩 있다.** 지금 선택한 프로젝트의 폴더에서 열리고, 프로젝트를 바꾸면 화면도 그 프로젝트의 것으로 바뀐다. **돌아오면 작업하던 내용이 그대로 남아 있다**(2026-11-23).

평소 쓰는 셸이고 입력하는 것도 동작하는 것도 평소와 같다. 실행 중인 명령은 **`Ctrl`+`C`로 멈추고**, 셸 자체는 `exit`으로 끝낸다. 끝나면 `[shell closed]`가 표시되는데, **Terminal 탭을 한 번 더 누르면** 새 셸이 그 화면 아래에서 시작한다 — 이미 그 탭에 있어도 누르면 된다. 직전까지의 출력은 지워지지 않는다(2026-11-23).

드래그해서 놓으면 선택한 글자가 클립보드로 가고, **오른쪽 버튼**이 붙여넣는다. `Ctrl`+`V`도 붙여넣고, `Ctrl`+`C`는 선택한 것이 있으면 복사한다(2026-11-19).

### Graph

프로젝트에 `graphify-out/graph.html`이 있으면 그대로 표시하고, 없으면 없다고 적는다(2026-11-23). 그래프를 만드는 도구는 Refdex와 별개이고, 없어도 나머지 기능은 그대로 동작한다.

## 문서 안의 명령

**셸 코드 블록이 곧 명령이다.** 등록하는 곳도, 이름이 정해진 파일도 없다.

문서의 코드 블록에 마우스를 올리면 오른쪽 위에 버튼이 뜬다 — **실행 버튼**은 터미널 탭에 입력하고, **복사 버튼**은 복사한다. 왼쪽 아래 COMMANDS 패널이 그 프로젝트의 **모든 문서에서** 셸 블록을 모아 한 줄씩 세운다.

**실행할 수 있는 블록인지는 블록의 언어로 판단한다.** ` ```bash `, ` ```powershell ` 같은 셸 언어로 적힌 것에만 실행 버튼이 붙고, ` ```text `처럼 다른 언어이거나 언어가 없으면 **복사 버튼**만 붙는다. 명령 패널에 올리고 싶지 않으면 언어를 바꾸면 된다.

**실행 버튼은 입력만 하고 마지막 Enter는 누르지 않는다.** 입력된 내용을 읽고 사용자가 누르는 구조다. 바로 실행되게 하려면 그 블록 **마지막에 빈 줄 하나**를 둔다.

## 문서끼리는 링크로 잇는다

화면에 파일 목록을 두지 않기 때문에, **문서가 스스로 경로를 쥐고 있어야 한다.**

- 메인 문서에 그 프로젝트의 문서 목록을 표로 둔다
- 메인 문서를 뺀 각 문서 맨 위에 **같은 상단 링크 줄**을 둔다. 모든 문서가 거기 있으므로 어느 문서에서든 한 번에 이동한다
- 아무도 링크하지 않는 문서는 검색으로만 도달한다

앞뒤로 이동하는 버튼은 없다 — 되돌아가는 것이 아니라 가려는 곳으로 바로 간다([D15](ARCHITECTURE.md)).

## 매일 쓰는 흐름

문서를 고치는 것은 편집기가 하고 Refdex는 읽기만 한다.

1. 편집기로 `.md`를 고치고 저장한다
2. **3초 안에 화면이 자동으로 따라온다.** 읽던 위치도 그대로다(2026-11-21)

문서는 지정한 폴더에서 그때그때 읽으므로 **다시 빌드할 일이 없다.** 다시 빌드해야 하는 것은 `ui/index.html`을 고쳤을 때뿐이다.

## 어디에 무엇이 저장되나

| 무엇 | 어디 |
| :--- | :--- |
| 읽을 폴더 | **아무 데도 저장되지 않는다.** 바로가기가 쥐거나 그 창에서만 유지된다 |
| 패널 너비 | 그 브라우저의 `localStorage` |

**앱이 디스크에 쓰는 것은 없다.** 프로젝트 폴더에도, 자체 설정 폴더에도 쓰지 않는다. 그래서 Refdex를 지워도 흔적이 남지 않는다.

## 알아 둘 제약

- **아무도 링크하지 않는 문서에는 도달할 수 없다.** 고칠 곳은 Refdex가 아니라 그 문서를 가리켜야 할 문서다
- **패널 너비는 이 브라우저에만 저장된다.** 다른 기계에서 열면 기본 너비다
- **시작 화면으로 돌아가는 버튼은 없다.** 다른 폴더로 가는 것은 `PROJECT` 옆 버튼이다
- **새 셸은 이전 셸의 입력 기록을 물려받지 않는다**
- **터미널에서 드래그만 해도 클립보드가 덮인다**
- **History 패널은 바뀐 줄만 보여 준다.** 그 시점 문서 전체를 다시 그리지는 않는다
- **바뀐 줄은 원본 그대로 표시된다** — `**`나 `|`가 글자로 남는다
- **제목이 바뀌었거나 사라진 커밋은 누를 수 없다.** 이동할 곳이 없으므로 `gone`이 붙는다
- **제목 앵커는 무시된다.** `A.md#제목` 링크는 `A.md`를 열고 그 위치로 스크롤하지는 않는다
- **`.md`가 아닌 링크는 열리지 않는다.** 폴더 밖을 가리키는 링크는 확인을 거쳐 기본 브라우저로 넘어간다
