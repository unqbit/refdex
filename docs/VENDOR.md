# 포함한 라이브러리

[README](../README.md) / `docs` — [ARCHITECTURE](ARCHITECTURE.md) · [USING](USING.md) · [COMMANDS](COMMANDS.md) · [VENDOR](VENDOR.md)

Refdex가 기대는 남의 것을 전부 적는다 — 포함한 파일, 화면 안에 직접 넣은 것, 앱이 빌드될 때 들어가는 것, 그리고 기계에 깔려 있어야 하는 것까지. **왜** 포함하는지는 [ARCHITECTURE 결정 기록](ARCHITECTURE.md)의 `D14`에 있고, 그래프 것을 어떻게 건네는지는 `D9`에 있다.

Refdex 자신은 **Apache-2.0**이다. 전문은 뿌리의 `LICENSE`에, 아래 것들의 고지는 `NOTICE`와 `ui/LICENSES/`에 있다 — 셋 다 `.md`가 아니라 이 화면에서는 열리지 않는다.

| :--- | :--- | :--- | :--- | ---: |
| `ui/mermaid.min.js` | 11.17.2 | MIT | 문서 속 ` ```mermaid ` 블록 | 3,572,661 |
| `ui/xterm.js` | 미상(확인 못 함) | MIT | 터미널 화면 | 488,663 |

## 기계에 설치되어 있어야 하는 것

받아 두지도 넣지도 않는다. 없으면 그 자리만 까닭을 적고 멈춘다 — 무엇이 멈추는지는 [ARCHITECTURE](ARCHITECTURE.md)의 "바탕에 기대는 것"에 있다.

| 무엇 | 확인한 판 | 없으면 |
| :--- | :--- | :--- |
| `git` | **시작 화면이 물어본다** | History 탭이 까닭을 적는다 |
| WebView2 | 윈도우 11에 기본으로 깔려 온다. **Edge 브라우저와는 다른 프로그램이다** — 따로 깔리고 판도 따로 간다 | 창이 서지 않는다 |
| 셸 | `ComSpec`이 가리키는 것 (윈도우), `$SHELL` (그 밖) | 터미널 탭이 까닭을 적는다 |
| 글꼴 | `Segoe UI Variable`·`Malgun Gothic`은 윈도우 11에 깔려 온다. `Noto Serif KR`(SIL OFL)과 `Cascadia Mono`(SIL OFL)는 깔려 있으면 쓴다 | 다음 글꼴로 내려간다. 마지막은 `serif`·`monospace`라 글자는 늘 나온다 |

**글꼴은 포함하지 않는다.** 이름으로 호출하고 없으면 다음 글꼴로 넘어간다(`D44`). 한글 글꼴은 파일이 커서 실행 파일에 그만큼 붙는데, 깔린 것으로 같은 값을 얻을 수 있으면 포함할 이유가 없다. 그래서 이 줄의 둘은 **기대는 것이지 가진 것이 아니다** — 없는 기계에서도 글자는 나오고 모양만 달라진다.

버전을 적어 두는 것은 올릴 때 기준이 되라는 뜻이다. 돌려 확인한 것에는 날짜가 붙어 있고, 날짜 없는 줄은 파일을 읽어 안 것이다.

시작 화면의 `WebView` 줄은 **WebView2 런타임의 판**이지 Edge 브라우저의 판이 아니다. 둘은 따로 깔리는 다른 프로그램인데 WebView2가 Edge와 같은 코드에서 나왔기 때문에 제 이름을 `Edg/`로 댄다 — 이 기계에서 재 보니 브라우저는 `158.0.4370.33`, 런타임은 `157.0.4341.60`이었고 화면에 선 것은 뒤엣것이다(2026-11-22).

**다만 실행 중인 버전은 이 문서가 쥐지 않는다.** 문서에 베껴 적은 숫자는 적은 날에만 맞고 그다음부터는 조용히 틀리기 때문이다. Refdex와 Tauri의 버전은 빌드할 때 코드에 박히고, `git`과 웹뷰는 쓸 때 물어본다 — 넷 다 **시작 화면**에 선다(2026-11-21). 이 문서가 쥐는 것은 **무엇을 골랐고 왜 골랐으며 어떻게 올리나**다.

## 직접 넣은 것

파일로 두지 않고 `ui/index.html` 안에 선 데이터만 옮겨 적은 것이다. 몇 개뿐이라 파일을 늘릴 값이 없었다.

| 어디서 | 라이선스 | 무엇을 | 어디에 |
| :--- | :--- | :--- | :--- |
| [Lucide](https://lucide.dev) | ISC | `play` `copy` `check` `arrow-left` `folder` | `ui/index.html`의 `ICONS` |

`https://github.com/lucide-icons/lucide`의 `icons/<이름>.svg`에서 가져왔다(2026-11-20). `24×24` 격자에 선 굵기 `2`로 그려진 것을 그대로 옮기고, 14px로 세우느라 굵기만 `2.25`로 올렸다. 늘릴 때는 이 표에 더한다 — 수가 많아지면 그때 파일로 뺀다.

## 우리가 그린 것

창 아이콘은 남의 것이 아니다. Refdex와 같은 **Apache-2.0**이다.

| 파일 | 무엇 |
| :--- | :--- |
| `src-tauri/icons/icon.svg` | 원본. `32` 격자, 네모난 모서리 |
| `src-tauri/icons/icon.ico` | 창과 실행 파일이 쓰는 것. `16 24 32 48 64 128 256`을 한 파일에 담았다 |
| `src-tauri/icons/icon.png` | `512`. 창이 아닌 바탕에서 쓴다 |
| `src-tauri/icons/installer-banner.bmp` | 설치 마법사 가운데 화면들의 띠. `493×58`, 흰 바탕 오른쪽에 아이콘 `40` |
| `src-tauri/icons/installer-dialog.bmp` | 설치 마법사 첫 화면과 끝 화면의 **바탕 전체**. `493×312`. 왼쪽 `164`에만 앱 화면을 그리고 **나머지는 흰색으로 둔다** — 마법사가 그 위에 검은 글씨를 쓰기 때문이다. 읽은 폴더도 문서 이름도 들어 있지 않다 |

그림은 **이 앱의 화면 배치**다 — 왼쪽 기둥이 위아래로 갈리고, 가운데가 서고, 오른쪽 문서 패널만 색이 다르다. 네모 다섯뿐이고 곡선도 선도 없다.

| 무엇 | 자리 (32 격자) | 색 | 화면의 어느 값 |
| :--- | :--- | :--- | :--- |
| 버전 | `1,1` `30×30` | `#181818` | `--panel` |
| 왼쪽 위 | `5,5` `6×12` | `#3d3d3d` | `--lit` |
| 왼쪽 아래 | `5,19` `6×8` | `#3d3d3d` | `--lit` |
| 가운데 | `13,5` `6×22` | `#3d3d3d` | `--lit` |
| 오른쪽 | `21,5` `6×22` | `#58a6ff` | `--accent` |

기둥 너비는 모두 `6`, 기둥 사이는 모두 `2`, 판(plate) 안쪽 여백은 네 변 모두 `4`다. 숫자가 전부 정수라 `16 32 64 256`으로 줄여도 칸 경계가 픽셀 사이에 끼지 않는다.

**색은 앱 화면의 것 그대로다.** 셋 다 스타일시트의 변수에서 가져온다 — 바탕은 패널의 색, 기둥은 밝히는 색, 오른쪽 하나는 강조색이다. 아이콘이 제 색을 따로 쥐면 화면의 색을 고칠 때마다 아이콘이 조용히 옛말을 하게 된다. 특히 오른쪽 기둥은 **링크와 같은 파랑**이라, 앱의 표가 앱 안의 색과 같은 말을 한다.

옆 그림 속 앱 화면도 같은 값으로 그린다 — 패널 이름은 화면과 같은 고정폭이다. 설치 마법사 그림 둘은 **BMP여야 하고 크기가 정해져 있다** — WiX가 그렇게 받는다. 둘 다 **글씨가 그 위에 얹히므로** 글씨 자리는 밝아야 한다: 띠는 통째로 희고, 옆 그림은 왼쪽 `164`만 칠하고 나머지를 희게 둔다. 옆 그림을 `164`보다 넓게 칠하면 첫 화면의 글씨가 어두운 바탕 위에 얹혀 읽히지 않는다(2026-11-22). 주지 않으면 WiX 제 로고가 대신 들어간다(2026-11-21).

**픽셀은 같은 숫자를 보고 한 번 더 그렸다.** 이 기계에 SVG를 픽셀로 바꾸는 도구가 없기 때문이고, 네모뿐이라 둘이 어긋날 데가 없다. `icon.svg`를 고치면 `.ico`와 `.png`도 다시 그려야 한다 — 그 일을 하는 도구는 두지 않았다. 빌드한 실행 파일에서 아이콘을 도로 꺼내 보니 `#181818`·`#3d3d3d`·`#58a6ff` 셋뿐이었다 — 크기마다 격자에서 새로 그리므로 줄이면서 생기는 중간색이 없다(2026-11-22). **아이콘만 고치면 실행 파일에는 들어가지 않는다** — 빌드 스크립트가 다시 돌아야 하므로 `src-tauri/build.rs`를 건드려 다시 돌린다(2026-11-22).

## 버전을 어떻게 확인했나

- **mermaid** — 앱에서 `info` 다이어그램을 그려 보니 스스로 `v11.17.2`라고 적었다 (2026-11-19). 묶음 안의 `version:"11.17.2"`와도 맞고, 묶음에 `12.x`를 말하는 자리는 없다.
- **vis-network** — 머리글에 `@version 9.1.6`이라고 적혀 있고, 그래프를 만드는 도구가 `graph.html`에 적어 두는 `sha384` 해시와 바이트까지 일치한다.
- **xterm 셋** — 파일 안에 판이 적혀 있지 않다. 파일 이름이 `xterm-addon-fit.js`인 것으로 5.4 앞의 `xterm` 묶음임은 알 수 있다 — 5.4부터 `@xterm/addon-fit`으로 이름이 바뀌었다. 정확한 판은 받아 둘 때 적어 두지 않아 모른다.

## 버전을 올릴 때

1. 지금 판을 위 표에서 본다. 최신 판은 npm 레지스트리에서 본다.
2. 받아서 `ui/`에 덮고, **이 문서의 판·크기·해시를 같은 변경 안에서 고친다.**
3. 판을 모르는 것은 올릴 때 판을 아는 것으로 바꿔 기준을 만든다.
4. `vis-network`를 올리면 `src-tauri/src/main.rs`의 `GRAPH_LIB_TAG`에 적힌 버전도 같이 고친다. `graph.html`이 요청하는 버전과 일치할 때만 우리 파일로 바꿔 전달하기 때문이다(`D9`).
5. 바뀐 자리만 앱에서 본다 — mermaid는 문서의 그림, xterm은 터미널 패널, vis-network는 그래프 패널이다.

Apache-2.0은 고지를 요구한다. `vis-network.min.js`는 머리글에 저작권과 라이선스를 품고 있고, 그 파일을 그대로 두는 것이 그 고지다 — 지울 일이 없다.
